# 광고 집행 인수인계 (ads/)

lottodraw.kr 광고 집행 전용 세션이 이 파일 하나로 이어 받도록 쓴다. 저장소 전체 규칙은 루트 `README.md`(특히 5장 작업 방식 · 문구 규칙)를 따른다.
이 파일은 사이트에 올라가지 않는다(`_config.yml` exclude). 같은 폴더의 이미지 · `index.html` 은 사이트에 올라간다.

- 처음 씀: 2026-11-11 (개발 세션에서 넘김)
- 광고 결과 · 결정은 맨 아래 **기록** 표에 날짜순으로 쌓는다. 큰 결정은 루트 README 4-10 · 6장에도 한 줄.

## 0. 지켜야 할 것 (사장님 규칙)

- 사장님과는 **한국어 다나까 말투**.
- 광고 문구 · 이미지 어디에도 쓰지 않는 말: **예측, 적중률, 추천 번호, 확률 상승, "명당"**, 그리고 **"복권은 사지 않아도 됩니다"**(배너 · 광고에 넣지 않기로 결정, #194).
- 복권은 **만 19세 이상** — 연령 타기팅에서 18–24 구간은 뺀다(구글은 19세만 따로 고를 수 없음).
- 부가세(VAT) 관련 일은 하지 않는다. 저장소를 비공개로 바꾸지 않는다.
- 사장님 이메일 · 개인 정보는 외부 서비스(광고 플랫폼 문의 양식 포함)에 넣지 않는다 — 넣어야 하면 사장님이 직접.
- 위치 개인정보: 광고 · 홍보물에 회원이 **어느 판매점 · 어느 칸 · 어느 지역**에 다녀왔는지 보이면 안 된다(처리방침: 방문 장소 비공개 · 제3자 제공 없음). 실제 지도 화면을 쓸 땐 닉네임 · 칸 주인이 읽히지 않게.
- 돈이 나가는 일(게시 · 예산 올리기 · 결제 수단)은 **반드시 사장님 확인 뒤**. 탭제어 Claude 에게는 결제 정보 입력을 시키지 않는다.
- 저장소 작업 방식: `html` 가지에서 새 가지 → PR → 직접 스쿼시 머지(`expectedHeadSha` 는 40자 전체). PR 본문은 **바꾼 것 / 확인한 방법 / 사용자가 할 일**. 커밋 · PR 에 모델 이름을 쓰지 않는다. 작업 끝에는 루트 README 6(진행 기록) · 7(할 일) 갱신.
- 다른 세션(사이트 개발)과 같은 저장소를 쓴다. 사이트 코드를 고쳐야 하면 작게, 겹치지 않게.

## 1. 무엇을 광고하나

**LottoHex — 로또 판매점 땅따먹기**: 지도를 육각형 칸으로 나누고, 판매점에 실제로 다녀와 GPS 현장 인증을 하면 그 칸을 차지하는 무료 게임(로그인 필요 · 만 19세 이상).

- 도착 페이지: <https://www.lottodraw.kr/lottohex.html> (LottoHex 전용), 판매점 지도 <https://www.lottodraw.kr/store-map.html>
- 설명 글: <https://www.lottodraw.kr/blog/lottohex-how-to-play.html>
- 규칙(광고 문구가 사실과 맞아야 한다 — `worker/src/community.js` 의 `POINTS`):
  - 현장 인증 **10P**(같은 곳 하루 1번, 하루 최대 50P) · 분기 Map 랭킹 보상(1위 1,000P · 2위 500P · 3위 300P · 4–10위 100P)
  - 칸을 모으면 칭호(마일스톤), 영역 빛 벽 300P, 칸 모양 바꾸기 30P
  - 점령 · 빼앗기 소식은 닉네임 · N번째 블록만 공개(어느 칸인지는 비공개)
- 1등 · 2등 판매점 지도, 전철역 · 지역 검색도 있다(판매점 지도 쪽 광고를 할 때 쓸 거리).
