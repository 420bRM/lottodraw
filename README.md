## 3. 자동 갱신은 어떻게 돌아가나 (GitHub Actions)

> **GitHub Actions란?** GitHub가 빌려주는 임시 컴퓨터가 정해진 시간에 저장소의
> 대본(`.github/workflows/*.yml`)대로 명령을 실행해 주는 기능이다. 내 컴퓨터가
> 꺼져 있어도 돌아간다.

```
① 예약 시간 도달
   · 일요일 03:10 (토요일 밤 추첨 결과 수집)
   · 월요일 09:10 (1등 당첨금이 늦게 확정되는 경우 보정)
        ↓
② 동행복권에서 새 회차를 받고, 최근 3회차를 다시 확인
   → 바뀐 게 없으면 여기서 끝
        ↓
③ 통계 페이지, 회차 페이지, 사이트맵을 새 데이터로 다시 생성
        ↓
④ "github-actions[bot]" 이름으로 저장소에 저장(커밋)
        ↓
⑤ GitHub Pages에 재배포 요청 → 사이트 반영
```

- **실제 실행은 예정보다 2~5시간 늦는 게 보통이다.** GitHub 예약 실행은 정시를
  보장하지 않는다. 일요일 오전 중에 반영되면 정상이다.
- **동행복권 데이터를 브라우저에서 직접 불러오지 않는 이유:** 동행복권 서버가
  다른 사이트에서의 호출을 막는다(CORS라는 브라우저 보안 규칙). 그래서 GitHub의
  임시 컴퓨터가 대신 받아서 `lotto-data.json` 파일로 저장해 두고, 사이트는 그
  파일만 읽는다.
- **실행 기록 보는 법:** GitHub 저장소 → 상단 **Actions** 탭. 초록 체크는 성공,
  빨간 X는 실패다.
- **수동 실행:** Actions 탭 → 왼쪽 `update-lotto-data` → **Run workflow** 버튼.
- **주의:** 예약 실행은 저장소의 기본 브랜치(`html`)에 있는 대본만 돈다.

## 4. 유료화: Polar 거절됨 (2026-09-27)

**결론: Polar로는 결제를 받을 수 없다.** 심사와 이의신청이 모두 거절됐다.

> Your product appears to provide paid tools or information connected to
> lottery play. Gambling and lottery-related products are not supported
> under our policies.

거절 사유가 "도박이라서"가 아니라 **"복권 관련이라서"** 다. 베팅을 받지
않고 예측도 하지 않는다는 점을 이의신청에 상세히 적었지만 그대로 거절됐다.
즉 문구를 고쳐 재제출해도 결과는 같다. **Polar는 닫힌 길이다.**

### 지금 코드 상태

- 결제 버튼은 "결제 준비 중"으로 표시된다 (`checkoutUrl`을 비워 둠)
- 조직 ID와 혜택 ID는 남아 있어 이미 발급된 키의 확인은 동작한다
- 지운 결제 링크 4개는 커밋 `6017b78`에 있다
- 유료로 잠가 둔 기능: 5개월(22회차) 통계, 홈의 상세 분석 4종

### 방향과 현재 결정 (2026-09-27)

**방향은 A(국내에서 직접 판매). 다만 실행은 보류.** 사이트는 지금 상태로
그대로 두고, 재개할 때 아래에서 이어서 시작한다.

| | 내용 | 비용과 위험 |
|---|---|---|
| **A1. 정식 PG 연동** | 토스페이먼츠·나이스페이 등과 계약 | 업종 추가(홈택스) → 통신판매업 신고(구청) → PG 심사. 서류·심사에 2~4주. **PG 심사에서도 사행성으로 거절될 수 있다** |
| **A2. 스마트스토어·크몽 판매** | 이용권 코드를 상품으로 팔고, 코드를 사이트에 입력해 해제 | 결제·통신판매 신고·세금을 플랫폼이 대신 처리. 수수료 5~6%, 구독 불가(일회성만). **며칠이면 연다** |
| **B. 광고 중심** | 잠근 기능을 풀고 애드센스에 집중 | 심사·세금·환불이 사라지지만 수익이 낮다 (아래 추정) |
| **C. 다른 해외 결제사** | Paddle, Lemon Squeezy 등 | 같은 금지 조항이 있어 같은 결과가 예상된다. 우선순위 낮음 |

재개한다면 **A2 → 검증되면 A1** 순서를 권한다. 한 건도 팔리지 않은 상태에서
몇 주짜리 서류와 심사 위험을 먼저 감수할 이유가 없다.

**A를 하려면 새로 만들어야 하는 것:** Polar는 결제·키 발급·키 검증을 모두
대신해 줬지만, 국내 PG는 결제만 한다. 키 발급과 검증은 직접 만들어야 하고,
PG 비밀키를 둘 서버도 필요하다(지금은 GitHub Pages 정적 사이트라 서버가
없다). Cloudflare Workers가 현실적인 선택지다 — detailcrop 에서 이미 쓴다.

**B의 수익 추정** (한국어 유틸리티 사이트 애드센스 RPM 1,000PV당 1,000~3,000원):
월 5,000PV면 5천~1만 5천원, 3만PV면 3~9만원, 10만PV면 10~30만원.
저트래픽에서는 A가 유리하다 — 광고는 1,000명이 와야 몇천 원이지만
이용권은 한 명만 사도 그만큼이다.

**진짜 병목은 결제 수단이 아니라 트래픽이다.** 월 5,000 방문에서 1%가
사면 월 3만원이다. 결제를 붙이는 일과 별개로 검색 유입을 늘리는 것이
수익을 결정한다.

시도한 것: Polar (거절), Polar 이의신청 (거절).
## 4-1. 영어 전환은 어떻게 되어 있나

머리글의 **KO / EN** 단추로 바뀐다. `https://www.lottodraw.kr/?lang=en` 처럼
주소로 바로 열 수도 있고, 고른 언어는 그 브라우저에 기억된다.

**문장을 고칠 곳은 두 군데뿐이다.**

1. **`js/i18n-dict.js`** — 회차가 바뀌어도 그대로인 문장(메뉴, 버튼, 안내).
   HTML 에는 `data-i18n="키"` 만 붙어 있고 한국어 원문도 그대로 남아 있다.
2. **`tools/build-static-stats.js`** — 회차마다 숫자가 달라지는 해설.
   `pEn(한국어, 영문)` 처럼 영문을 나란히 적어 두면 생성기가
   `data-i18n-en` 속성에 같이 찍는다.

주의할 점:

- **스크립트가 `I18N.t()` 로 꺼내 쓰는 키는 사전에 `ko` 도 적어야 한다.**
  화면에 붙은 문장과 달리 HTML 에 원문이 없기 때문이다.
- 언어를 바꾸면 페이지를 다시 읽는다. 차트를 부분적으로 다시 칠하는 것보다
  한 번 새로 그리는 쪽이 어긋날 여지가 없다.
- **검색 노출은 한국어 기준이다.** 기본 언어가 한국어이고 영문은 속성에만
  들어 있어, 구글은 지금처럼 한국어 페이지로 읽는다. 영어권 검색까지 노리려면
  `/en/` 주소로 영어 페이지를 따로 생성해야 한다 (같은 사전을 쓰므로 번역을
  다시 할 필요는 없다).

## 5. 작업 방식과 주의사항

### 브랜치

> **브랜치란?** 같은 저장소 안의 별도 작업 공간이다. 실제 사이트는 `html`
> 브랜치 하나에서 나온다.

- **`html`이 실제 사이트다.** 여기에 올라간 것이 곧바로 배포된다.
- Claude(웹)가 작업하면 `claude/…` 브랜치에서 고친 뒤 **Pull Request**(변경
  제안서)를 만든다. GitHub에서 **Merge** 버튼을 눌러야 `html`에 합쳐진다.

### ⚠️ 옛 파일로 덮어쓰지 말 것

**봇이 매주 `html` 브랜치에 직접 저장한다.** 그래서 GitHub에 있는 파일이 항상
내 컴퓨터(Dropbox 날짜 폴더)의 파일보다 최신이다.

로컬에 있던 옛 파일을 GitHub 웹 업로드로 올리면 **봇이 넣은 최신 회차가 이전
상태로 되돌아간다.** 에러도 나지 않는다. 특히 조심할 파일:

`lotto-data.json` · `index.html` · `draws.html` · `statistics-*.html` ·
`sitemap.xml` · `round/` · `tax.html` · `top-prize.html` · `probability.html`

**수정할 파일은 항상 GitHub에서 최신본을 받아서 고친다.**

### 문구 규칙

- **"당첨 확률을 올려준다"는 뉘앙스의 문구는 쓰지 않는다.** 로또는 모든 조합의
  확률이 같다. "확률 상승", "적중률", "추천 번호", "AI 예측" 금지.
- 통계는 "지나간 기록이 이랬다"까지만 보여준다. 예측으로 읽히게 쓰지 않는다.

### 참고: 옛 계획 문서

Dropbox `260914 클로드` 폴더의 README와 CLAUDE.md는 **실제로 적용되지 않은 초기
계획**이다(Python, `templates/` 폴더, Cloudflare 배포 기준). 지금 구조와 다르니
그 문서의 파일 경로나 배포 설명을 따르지 말 것. 이 README가 기준이다.
