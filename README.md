# lottodraw.kr

로또 6/45 번호 생성기와 전 회차 통계 사이트. 주소는 <https://www.lottodraw.kr>.

이 문서는 **작업 인수인계서**다. 회사 PC, 집 PC, Claude 채팅, VS Code 등 어디서
작업하든 이 파일 하나만 읽으면 "지금 어디까지 왔고, 다음에 뭘 해야 하는지"를 알 수
있도록 쓴다. 작업을 마칠 때마다 맨 아래 **진행 기록**에 한 줄씩 추가한다.

> **Claude에게:** 작업을 시작하기 전에 이 문서를 끝까지 읽을 것. 작업이 끝나면
> "진행 기록"과 "할 일"을 갱신하는 것까지가 작업이다.

### 기타 파일

- `CNAME`: 사이트 주소(www.lottodraw.kr)를 GitHub Pages에 알려주는 파일
- `ads.txt`: 구글 애드센스 광고 인증 파일
- `naver….html`: 네이버 서치어드바이저 소유 확인 파일. **지우면 안 된다**
- `robots.txt` `sitemap.xml`: 검색엔진용 안내 파일
- `_config.yml`: GitHub Pages(Jekyll) 설정. 블로그 원고(`content/`)가 `/content/blog/…html` 이라는 중복 페이지로 올라가지 않게 뺀다
- **방문자 통계(Cloudflare Web Analytics)**: 모든 페이지 `</head>` 바로 앞에 비콘 스크립트 한 줄이 있다. DNS가 "DNS only"(프록시 꺼짐)라 클라우드플레어가 자동으로 넣어주지 않으므로 직접 심은 것이다. 생성 페이지는 `tools/build-static-stats.js`의 `CF_BEACON`에서, 손으로 관리하는 페이지(`index` `about` `contact` `privacy` `terms` `statistics` `tax` `top-prize`)는 각 파일에 직접 들어 있다. **새 페이지를 손으로 만들면 이 줄도 복사해 넣을 것**

## 3. 자동 갱신은 어떻게 돌아가나 (GitHub Actions)

> **GitHub Actions란?** GitHub가 빌려주는 임시 컴퓨터가 정해진 시간에 저장소의
> 대본(`.github/workflows/*.yml`)대로 명령을 실행해 주는 기능이다. 내 컴퓨터가
> 꺼져 있어도 돌아간다.

```
① 예약 시간 도달
   · 일요일 03:10 (토요일 밤 추첨 결과 수집)
   · 월요일 09:10 (1등 당첨금이 늦게 확정되는 경우 보정)
        ↓
② 동행복권에서 새 회차를 받고, 최근 3회차를 다시 확인
   → 바뀐 게 없으면 여기서 끝
        ↓
③ 통계 페이지, 회차 페이지, 블로그, 사이트맵을 새 데이터로 다시 생성
        ↓
④ "github-actions[bot]" 이름으로 저장소에 저장(커밋)
        ↓
⑤ GitHub Pages에 재배포 요청 → 사이트 반영
```

- **실제 실행은 예정보다 2~5시간 늦는 게 보통이다.** GitHub 예약 실행은 정시를
  보장하지 않는다. 일요일 오전 중에 반영되면 정상이다.
- **동행복권 데이터를 브라우저에서 직접 불러오지 않는 이유:** 동행복권 서버가
  다른 사이트에서의 호출을 막는다(CORS라는 브라우저 보안 규칙). 그래서 GitHub의
  임시 컴퓨터가 대신 받아서 `lotto-data.json` 파일로 저장해 두고, 사이트는 그
  파일만 읽는다.
- **실행 기록 보는 법:** GitHub 저장소 → 상단 **Actions** 탭. 초록 체크는 성공,
  빨간 X는 실패다.
- **수동 실행:** Actions 탭 → 왼쪽 `update-lotto-data` → **Run workflow** 버튼.
- **주의:** 예약 실행은 저장소의 기본 브랜치(`html`)에 있는 대본만 돈다.

## 4. 유료화: 계좌이체 직접 판매로 전환 (2026-10-01)

**결론: 카드 결제는 국내외 어디서도 막혀 있다. 그래서 내 계좌로 직접 받고,
입금되면 사람 손 없이(새벽에도) 서버가 서명한 이용권 키를 바로 내주는 방식으로 바꿨다.**
입금 확인 · 키 발급 · 점검이 전부 자동이다. 사람이 하는 일은 **드물게 오는 환불 문의를 확인하는 것**
하나뿐이다. 키 발급 뒤 단순 변심 환불은 없다(약관 4조, 2026-10-02 개정).
코드는 완성돼 있고, 남은 것은 처음 한 번의 설정(아래 설치 순서)뿐이다.

### 어떻게 돌아가나

```
구매자: 이용권 고름 → 입금자명 적고 주문
        → 화면에 내 계좌와 "주문마다 다른 금액"이 뜸 (예: 5,900원이 아니라 5,866원)
        → 계좌이체 (모바일은 "토스 앱으로 보내기" 버튼)
내 휴대폰: 은행 입금 알림을 받으면 그 내용을 서버로 그대로 넘김 (MacroDroid / 아이폰 단축어)
서버:   알림 속 금액 5,866원 = 입금 대기 주문 하나 → 그 주문이라고 보고 키 발급
구매자: 열어 둔 화면이 10초마다 확인하다가 키를 받아 바로 잠금 해제 (보통 1분 안)
```

- **주문마다 금액 끝자리가 다르다** (정가에서 1~99원 할인, 입금 대기 중인 주문끼리 겹치지 않게).
  그래서 입금자명이 달라도(가족 계좌, 법인 계좌 등) 금액만으로 주문을 찾는다. 금액이 같은
  대기 주문이 둘 이상이면 입금자명으로 한 번 더 좁히고, 그래도 애매하면 발급하지 않고 알린다.
  구매자가 안내 금액을 무시하고 **정가로 보내도**(예: 5,866원 대신 5,900원), 입금자명이 맞는 대기 주문이
  하나뿐이면 그 주문으로 보고 자동 발급한다. 덜 보냈거나 정가보다 많이 보냈으면 판매자 확인으로 넘긴다.
  "잔액 …원"은 금액으로 치지 않고, 같은 알림이 두 번 와도 한 번만 처리한다.
- **휴대폰 연결 지킴이**: 휴대폰은 6시간마다 "ping"을 보낸다. 서버가 한 시간마다 확인해서
  13시간 넘게 조용하면 텔레그램으로 알리고, 그동안 구매 화면은 "판매자 확인 뒤 열림"으로
  바뀐다(구매자를 속이지 않게). 이때 들어온 주문은 관리자 페이지에서 "입금 확인"을 누르면 된다.
- **환불은 두 경우뿐이고, 메일로 소명자료를 받는다** (약관 4조, 2026-10-02 개정): 상품이 "보는 것"이라
  키를 정지해도 본 내용은 돌아오지 않기 때문에 단순 변심 환불은 없다. 대신 전 회차·최근 10회차 통계를 무료로
  보여 준다(전자상거래법 제17조 제2항 제5호의 시용상품 제공). 환불하는 경우는
  ① **중복 결제**(이체 확인증·입출금 내역 캡처) ② **작동하지 않음**(오류 화면 캡처, 기기·브라우저 — 먼저 고쳐 주고
  못 고치면 환불)뿐이고, `contact@lottodraw.kr` 로 주문번호·돌려받을 계좌·소명자료를 받는다(문의 페이지 "환불 신청").
  확인되면 관리자 → 그 주문 → **"환불 처리(키 정지)"** 를 누르고, 계좌이체는 돈을 직접 보낸다(카드는 결제 취소까지 자동).
  약관에는 "이 밖에 법률이 청약철회를 인정하는 경우에는 그에 따른다"는 한 줄만 남겼다(법이 정한 권리는 약관으로 못 없앤다).
  **최종 문구는 법률 전문가에게 한 번 확인받기를 권한다.**
- **자동 점검**: 배포할 때마다, 그리고 매일 아침 6시 23분에 GitHub 가 실서버로
  주문 → 입금 알림 → 키 발급 → 브라우저 확인 → 관리자 환불 처리 → 키 정지를 해 보고 지운다
  (`worker/test/live-smoke.mjs`). 돈은 오가지 않는다. 실패하면 텔레그램과 GitHub 메일로 온다.
  **사람이 시험 구매를 할 필요가 없다.**
- **이용권 키는 서버가 서명하고, 확인은 방문자 브라우저가 혼자 한다** (ECDSA P-256).
  그래서 서버가 멈춰도 이미 산 사람은 열리고, 키를 외부로 보내지도 않는다. 형식은 `worker/src/keys.js` 첫머리.
- **페이앱이 승인되면**: 비밀값 3개만 넣으면 "카드 · 간편결제"가 나타나고, 결제 즉시 키 발급,
  관리자 환불 처리 때 결제 취소까지 자동이다. 휴대폰 연결도 필요 없다.
- 월 구독은 없앴다. 계좌이체는 자동 결제가 안 되기 때문이다. 1주·1개월·평생 3종.

   | `CLOUDFLARE_API_TOKEN` | 1번 토큰 |
   | `CLOUDFLARE_ACCOUNT_ID` | 1번 계정 ID |

   | `BANK_NAME` | `우리은행` |
   | `BANK_ACCOUNT` | 받을 계좌번호 (예: `1002-123-456789`) |
   | `BANK_HOLDER` | 예금주 이름 |

   deploy-worker → Run workflow). 첫 배포 때 저장소(KV)가 자동으로 만들어지고
   `api.lottodraw.kr` 이 연결되며, 이어서 자동 점검이 **서명 키와 입금 알림 열쇠를 만들고**
   주문부터 환불까지 한 바퀴 돌려 본다. Actions 탭에 초록 체크가 뜨면 서버 쪽은 끝이다.
   - 도메인 연결에서 실패하면: Cloudflare → Workers & Pages → `lottodraw-api` → Settings →
     Domains & Routes → Add → Custom domain → `api.lottodraw.kr`.
4. **휴대폰 입금 알림 연결 (한 번, 약 5분)**: <https://www.lottodraw.kr/admin.html> 에
   `ADMIN_TOKEN` 입력 → **"입금 알림 연결"** 카드의 안내대로 설정한다.

   - 아이폰: 은행 입출금 **문자 알림** 신청 → 단축어 자동화(메시지 수신)로 전달, 하루 여러 번 ping
   - 1~2분 안에 카드 상태가 "✔ 연결됨"이 되면 끝. 그 뒤로는 새벽 입금도 저절로 열린다.
   - 가능하면 **판매 전용 계좌**를 쓴다. 다른 입금(월급 등)도 서버로 넘어가기 때문이다
     (이용권 금액대가 아니면 무시하고 저장하지 않는다).
   - (권장) 같은 화면의 "서명 키 백업 복사" → GitHub Secret `LICENSE_PRIVATE_JWK`.
     Cloudflare 저장소를 잃어도 판매한 키가 살아난다. 이 값은 비밀이다.
5. **판매자 정보 넣기**: `js/premium-config.js` 의 `seller` 에 상호·대표자 등을 채운다
   (결제 페이지와 이용약관 아래에 표시). 전자상거래법상 판매자 신원 표시 의무가 있다.
6. (선택) **페이앱 가입 신청**: <https://www.payapp.kr> → 승인되면 판매자 사이트의 연동 정보에서
   `PAYAPP_USERID` `PAYAPP_LINKKEY` `PAYAPP_LINKVAL` 을 GitHub Secrets 에 넣고 deploy-worker 다시 실행.

### 운영 메모

- 관리자 페이지: `admin.html` (검색 제외, 메뉴에 없음). 토큰은 그 브라우저에만 저장된다. 방문자 통계 비콘은 일부러 넣지 않았다.
- 입금 대기 주문은 14일 뒤 저절로 지워진다. 입금 기한 안내는 72시간. 기한이 지난 주문은
  새 주문 상한(전체 50건, 한 IP 3건)에 세지 않는다. 늦게 입금되면 관리자 페이지에서 그대로 확인하면 된다.
- 관리자 페이지는 2분마다(최대 1시간) 저절로 새로고침한다. Cloudflare 무료 요금제의 KV 목록 조회 한도(하루 1,000회)를 아끼려는 것이다.
- 발급된 키는 KV 에 남고, 키를 잃어버린 구매자는 주문번호·입금자명으로 찾아 "키 보기"로 다시 보내 준다.
- 자동 확인이 안 된 입금(금액을 다르게 보냄 등)은 텔레그램으로 오고, 관리자 페이지에서 그 주문의 "입금 확인 → 키 발급"을 누르면 된다.
- 입금 알림 연결 주소: `https://api.lottodraw.kr/api/hooks/deposit` (머리글 `Authorization: Bearer 열쇠`). 열쇠는 관리자 페이지에서 복사한다. 바꾸려면 GitHub Secret `DEPOSIT_HOOK_SECRET` 을 넣으면 그 값이 우선한다.
- **서명 키를 바꾸거나 KV 를 지우면 이미 판 키가 전부 무효가 된다.** 건드리지 않는다.
- 서버 비밀값 목록과 설명: `.github/workflows/deploy-worker.yml` 첫머리, `worker/src/index.js`.
- 로컬 테스트: `cd worker && npm test` (Worker 와 브라우저 키 확인을 같이 검사).

## 4-1. 영어 전환은 어떻게 되어 있나

머리글의 **KO / EN** 단추로 바뀐다. `https://www.lottodraw.kr/?lang=en` 처럼
주소로 바로 열 수도 있고, 고른 언어는 그 브라우저에 기억된다.

**문장을 고칠 곳은 두 군데뿐이다.**

1. **`js/i18n-dict.js`** — 회차가 바뀌어도 그대로인 문장(메뉴, 버튼, 안내).
   HTML 에는 `data-i18n="키"` 만 붙어 있고 한국어 원문도 그대로 남아 있다.
2. **`tools/build-static-stats.js`** — 회차마다 숫자가 달라지는 해설.
   `pEn(한국어, 영문)` 처럼 영문을 나란히 적어 두면 생성기가
   `data-i18n-en` 속성에 같이 찍는다.

주의할 점:

- **스크립트가 `I18N.t()` 로 꺼내 쓰는 키는 사전에 `ko` 도 적어야 한다.**
  화면에 붙은 문장과 달리 HTML 에 원문이 없기 때문이다.
- 언어를 바꾸면 페이지를 다시 읽는다. 차트를 부분적으로 다시 칠하는 것보다
  한 번 새로 그리는 쪽이 어긋날 여지가 없다.
- **검색 노출은 한국어 기준이다.** 기본 언어가 한국어이고 영문은 속성에만
  들어 있어, 구글은 지금처럼 한국어 페이지로 읽는다. 영어권 검색까지 노리려면
  `/en/` 주소로 영어 페이지를 따로 생성해야 한다 (같은 사전을 쓰므로 번역을
  다시 할 필요는 없다).

## 4-3. 블로그는 어떻게 되어 있나

메뉴의 **블로그**(`blog/index.html`)에 사람이 쓴 글 15편이 있다. 4-2번의 "가치 있는
콘텐츠 부족" 반려에 대응해 2026-10-02에 올렸다. 머리글의 **KO / EN** 으로 영어도 된다.

```
content/blog/01-is-number-34-special.md      ← 한국어 원고. 글은 여기서 고친다
content/blog/en/01-is-number-34-special.md   ← 영어 원고. 파일 이름이 같아야 짝이 된다
        ↓  node tools/build-static-stats.js   (tools/build-blog.js 를 불러 쓴다)
blog/index.html                               ← 목록: 카테고리 단추, 앞부분 미리보기
blog/is-number-34-special.html                ← 글: 목차, 이어지는 페이지, 이전·다음 글
sitemap.xml                                   ← 블로그 주소 16개가 같이 들어간다
```

- **`blog/` 의 HTML 은 직접 고치지 않는다.** 생성기가 다시 만들면 덮어쓰인다.
- 원고를 고치면 `node tools/build-static-stats.js` 를 돌려 `blog/` 와 같이 커밋한다.
  잊어도 다음 일요일 자동 갱신 때 반영된다(워크플로가 `blog/` 도 다시 만들어 커밋한다).
- 블로그 페이지는 머리글에 최신 회차가 찍혀 있어서 매주 자동 갱신 때 같이 바뀐다. 정상이다.
- 원고(`content/`)는 사이트에 올리지 않는다. 그대로 두면 GitHub Pages(Jekyll)가 원고를
  `/content/blog/…html` 이라는 중복 페이지로 바꿔 올리기 때문에 `_config.yml` 에서 뺐다.

### 원고 쓰는 법

머리말(맨 위 `---` 사이):

```
---
title: 34번이 186회 나온 게 특별한가 — 표준편차로 읽는 출현 횟수
slug: is-number-34-special      ← 주소 blog/<slug>.html. 한 번 정하면 바꾸지 않는다
category: 통계 읽기              ← 당첨 이후 · 통계 읽기 · 번호 고르기 · 확률 기초
description: 목록과 검색 결과에 나오는 요약 한두 문장
date: 2026-10-01                 ← 화면에는 안 보인다. 사이트맵·검색엔진용
pick: 3                          ← 흥미도 1~3. 클수록 목록 위쪽에 올 가능성이 크다 (빼면 1)
related: [frequency]             ← 글 끝 "이 글과 이어지는 페이지"
updated: 2026-11-01              ← (선택) 크게 고친 날. 사이트맵·검색엔진에 갱신일로 간다
---
```

- 영어 원고의 머리말은 `title` 과 `description` 두 줄뿐이다.
- `related` 에 쓰는 이름: `frequency`(많이 나온 번호) · `gap`(미출수) · `pair`(궁합수) ·
  `ac`(AC값) · `sum`(합계) · `even-odd`(홀짝) · `low-high`(저고) · `consecutive`(연속번호) ·
  `prize-stats`(1등 당첨자 수) · `probability`(확률) · `tax`(실수령액) · `top-prize`(TOP 50) ·
  `generator`(번호 생성기). 새 이름이나 새 카테고리는 `tools/build-blog.js` 맨 위의
  `RELATED` · `CATEGORIES` 에 더한다.
- 본문 문법: `## 소제목`(목차가 저절로 생긴다), 빈 줄로 나눈 문단(문단 안에서 줄을 바꾸면
  줄바꿈), `- 목록`, `1. 목록`, `> 인용`, `| 표 |`, `**굵게**`, `` `코드` ``, `[링크](/tax.html)`.
  링크는 사이트 뿌리 기준(`/statistics-frequency.html`, `/blog/why-jackpots-split.html`)으로
  쓰면 생성기가 알맞게 고쳐 단다.
- 문구 규칙은 통계 페이지와 같다 — 예측·적중률·추천 번호는 쓰지 않는다([문구 규칙](#문구-규칙)).

### 영어 원고는 한국어와 블록 수가 같아야 한다

한국어 블록 하나에 영어 블록 하나가 짝지어져 `data-i18n-en` 속성으로 들어간다.
그래서 **소제목·문단·목록 항목·표 칸·인용의 수와 순서**가 한국어와 똑같아야 한다.
어긋나면 빌드가 아래처럼 경고하고 **그 글의 영어만 뺀다** (영어 화면에서 그 글만 한국어로 보인다).

```
  ! 블로그: en/04-why-jackpots-split.md 의 구조가 한국어와 다르다 — 7번째 블록: 한국어 p, 영어 h2. 이 글의 영어는 뺀다
```

빌드를 멈추지 않는 것은 일부러다. 매주 도는 자동 갱신이 원고 하나 때문에 서면 안 된다.

### 저절로 정해지는 것

- **목록 순서 (의도된 무작위)**: 방문할 때마다 `흥미도(pick) + 0~1.6 사이 무작위 값`으로
  줄 세운다. 흥미도 높은 글이 대체로 위에 오고, 이웃한 단계끼리는 섞인다.
  지금 흥미도: 3 = 도박사의 오류 · 기대값과 전망 이론 · 의사난수와 셔플,
  2 = 34번 · 당첨금 쪼개짐 · 명당 · 궁합수 · 연속 번호, 1 = 나머지(세금·수령·용어 등 실용 글).
  섞는 폭은 `tools/build-blog.js` 의 `PICK_JITTER`
- **카테고리 단추**: 그 카테고리 글이 맨 위로 가나다순(영어 화면은 알파벳순)으로 모이고,
  나머지는 흐리게 그 아래에 남는다. 자리 이동은 홈 막대그래프 정렬과 같은 미끄러지는
  애니메이션(움직임 줄이기 설정이면 바로 바뀜). '전체'를 누르면 처음 순서로 돌아간다
- **날짜·읽는 시간은 화면에 표시하지 않는다** (2026-10-02 결정)
- **목록 미리보기**: 본문 앞에서부터 표를 빼고 최대 5블록, 420자를 넘으면 멈춘다
- **이전 글 · 다음 글**: 흥미도 높은 순, 같으면 파일 번호 순 (HTML 에 적힌 순서)
- 원고를 지우거나 `slug` 를 바꾸면 옛 `blog/` 페이지는 생성기가 지운다

## 5. 작업 방식과 주의사항

### 브랜치

> **브랜치란?** 같은 저장소 안의 별도 작업 공간이다. 실제 사이트는 `html`
> 브랜치 하나에서 나온다.

- **`html`이 실제 사이트다.** 여기에 올라간 것이 곧바로 배포된다.
- Claude(웹)가 작업하면 `claude/…` 브랜치에서 고친 뒤 **Pull Request**(변경
  제안서)를 만든다. GitHub에서 **Merge** 버튼을 눌러야 `html`에 합쳐진다.

### ⚠️ 옛 파일로 덮어쓰지 말 것

**봇이 매주 `html` 브랜치에 직접 저장한다.** 그래서 GitHub에 있는 파일이 항상
내 컴퓨터(Dropbox 날짜 폴더)의 파일보다 최신이다.

로컬에 있던 옛 파일을 GitHub 웹 업로드로 올리면 **봇이 넣은 최신 회차가 이전
상태로 되돌아간다.** 에러도 나지 않는다. 특히 조심할 파일:

`lotto-data.json` · `index.html` · `draws.html` · `statistics-*.html` ·
`sitemap.xml` · `round/` · `blog/` · `tax.html` · `top-prize.html` · `probability.html`

**수정할 파일은 항상 GitHub에서 최신본을 받아서 고친다.**

### 문구 규칙

- **"당첨 확률을 올려준다"는 뉘앙스의 문구는 쓰지 않는다.** 로또는 모든 조합의
  확률이 같다. "확률 상승", "적중률", "추천 번호", "AI 예측" 금지.
- 통계는 "지나간 기록이 이랬다"까지만 보여준다. 예측으로 읽히게 쓰지 않는다.

### 참고: 옛 계획 문서

Dropbox `260914 클로드` 폴더의 README와 CLAUDE.md는 **실제로 적용되지 않은 초기
계획**이다(Python, `templates/` 폴더, Cloudflare 배포 기준). 지금 구조와 다르니
그 문서의 파일 경로나 배포 설명을 따르지 말 것. 이 README가 기준이다.
